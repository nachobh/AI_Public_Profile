GPU & Inference Systems (independent research, 2025 – present)

llama.cpp fork work on ROCm 7.2.4 / HIP and Vulkan, targets gfx1150/gfx1151 · all results measured on one machine against clean upstream builds (commit-pinned), first-run variance discarded

  • Kernel diagnosis: root-caused a four-way LDS shared-memory bank conflict in llama.cpp's Vulkan cooperative-matrix matmul via gcd(SHMEM_STRIDE, 32) analysis and a padding sweep; a padding-stride change (plus host shared-memory budgeting) delivered +14.1% prefill (272.8→311.3 tok/s, historical measurement vs upstream 95b8e33e1); the fix is re-ported onto the current merged branch with the full MUL_MAT suite green on Vulkan — the paired re-measurement is pending and will be reported as-is.
  • Quantization evaluation: built and evaluated a ROCmFP4 path (CPU/Vulkan kernels; HIP backend op integration open) for a 27B model against a strong K-quant baseline on identical hardware: 12% smaller, +7% batch-1 decode (12.56 vs 11.71 tok/s), PPL gap "small but probably real" (5.9842 ± 0.071 vs 5.8965 ± 0.070 — overlapping error bars, reported as such rather than as parity).
  • Flagship fix — FP4 batched spec-decode verification (Qwen3.8-27B, DFlash2, Vulkan): FP4 initially lost to the K-quant under spec decode (16.8 vs 22.3 tok/s at n-max 3) despite similar acceptance (52.7% vs 55.2%). Root cause: the batched mat-vec kernels were mis-tuned for the batch 3–8 verification range — per-call re-decoding of block scales and a branchy per-weight dequant path whose cost scaled linearly with batch — plus a mixed-type GGUF where a single Q6_0 output.weight tensor cost 22 ms/step. Fixed with whole-block scale amortization and a branch-free dequant: prose spec-decode 16.8 → 24.6 tok/s (+46%), batched gains +6% (B=1) → +65% (B=8), kernel-level n=8 mat-vec 312 → 173 µs.
  • Adaptive draft length for spec decode (shipped feature): acceptance signal was measured but discarded; added a per-sequence EMA controller whose key insight is that full acceptance censors the measurement (a lower bound, so it probes upward instead of averaging down). +48% prose / +33% JSON on a model-card-recommended fixed setting (best of four tested arms; roughly matches a tuned fixed setting elsewhere); turns n-max from a tuning parameter into a safety ceiling. Off by default; distribution-preserving.
  • Triton / training stack on AMD: measured +7% training throughput with experimental AOTriton; FlashAttention-Triton-AMD and MIOpen tuning; PyTorch/ROCm LoRA fine-tuning (PEFT) and diffusion benchmark sweeps (resolution × steps).
  • Systems-level: roofline-style analysis of ~256 GB/s UMA bandwidth ceiling (decode measured at 205–213 GB/s, 80–83% of theoretical — little kernel headroom left; launch/fusion opportunities remain); rewrote llama-quantize to stream in row bands (205 GB scratch → byte-identical output); KV-cache-to-RAM offload experiments; patched and DKMS-installed the amdgpu 31.50 driver for mainline kernel 7.1; one merged upstream llama.cpp PR — a UI/MCP fix (ggml-org/llama.cpp#28089), upstream-contribution proof rather than kernel work.
